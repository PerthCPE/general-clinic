# 2. Sequence Diagram (เลือก 1 Use Case จากแต่ละระบบย่อยที่รับผิดชอบ)

## Use Case ระบบย่อยที่ 1: บันทึกผลการตรวจและวินิจฉัยโรค (Record Examination and Diagnosis)

### 1. การวิเคราะห์องค์ประกอบ (Participant Identification)

**Actor (External to the System):**

- **แพทย์ (Doctor)** — ผู้ทำการตรวจรักษา บันทึกผลการตรวจร่างกาย และระบุผลการวินิจฉัยโรค

**Object (Internal to the System):**

- **ExaminationPage** — หน้าจอบันทึกการตรวจ ทำหน้าที่รับข้อมูลจากแพทย์และแสดงผลลัพธ์กลับ
- **ExaminationController** — ตัวควบคุมลำดับการทำงาน ตรวจสอบความถูกต้องของข้อมูล และสั่งบันทึกลงฐานข้อมูล
- **VisitRecord** — ข้อมูลการเข้ารับบริการหนึ่งครั้ง (VN) ใช้ดึงข้อมูลผู้ป่วยกับผลคัดกรอง และปรับสถานะเมื่อตรวจเสร็จ
- **Examination** — บันทึกผลการตรวจร่างกาย การประเมิน แผนการรักษา และคำแนะนำ
- **Diagnosis** — ผลการวินิจฉัยโรคตามรหัส ICD-10 (มีได้หลายรายการต่อการตรวจหนึ่งครั้ง)

### 2. การเขียน Scenario

**Main Scenario:**

1. แพทย์เลือกผู้ป่วยจากคิวและเปิดหน้าบันทึกการตรวจ
2. ExaminationPage ส่งคำขอข้อมูลของเคสที่กำลังตรวจไปยัง ExaminationController
3. ExaminationController ดึงข้อมูลการมาตรวจและผลคัดกรองจาก VisitRecord
4. VisitRecord ส่งข้อมูลผู้ป่วยและสัญญาณชีพกลับมา และระบบแสดงหน้าบันทึกการตรวจให้แพทย์
5. แพทย์กรอกประวัติการเจ็บป่วยปัจจุบันและผลการตรวจร่างกายรายระบบ
6. แพทย์เลือกรหัสวินิจฉัย ICD-10 โดยเลือกได้หลายรายการ (ทำซ้ำจนครบทุกการวินิจฉัย)
7. แพทย์กดบันทึกผลการตรวจ
8. ExaminationController ตรวจสอบความครบถ้วนของข้อมูลและสถานะของเคส
9. ExaminationController บันทึกข้อมูลลง Examination และ Diagnosis
10. ExaminationController ปรับสถานะของ VisitRecord เป็น Completed
11. ระบบแสดงข้อความบันทึกสำเร็จให้แพทย์

**Alternative Scenario:**

- **A1 ข้อมูลไม่ครบถ้วน** (ไม่ได้ระบุการวินิจฉัยหลัก หรือไม่ได้กรอกผลตรวจร่างกาย)
  ExaminationController ไม่บันทึกข้อมูลใดๆ และส่งข้อความแจ้งข้อผิดพลาดกลับไปแสดงที่หน้าจอ
  เพื่อให้แพทย์กรอกข้อมูลให้ครบก่อนบันทึกใหม่
- **A2 เคสถูกปิดไปแล้ว** (สถานะของ VisitRecord เป็น Completed)
  ระบบไม่อนุญาตให้แก้ไขข้อมูล และแจ้งเตือนว่าการตรวจครั้งนี้ถูกปิดแล้ว
- **A3 บันทึกฐานข้อมูลไม่สำเร็จ**
  ระบบยกเลิกการบันทึกทั้งชุด (rollback) เพื่อไม่ให้มีผลการตรวจที่ไม่มีการวินิจฉัยกำกับ
  แล้วแจ้งเตือนให้แพทย์บันทึกใหม่อีกครั้ง

### 3. การสร้าง Sequence Diagram

> ใช้ไฟล์ **SD1-RecordExaminationAndDiagnosis.xml** เปิดใน draw.io แล้ว Export เป็นรูปมาวางตรงนี้

องค์ประกอบ UML ที่ใช้ในไดอะแกรม

| สัญลักษณ์ | ใช้ตรงไหน |
|---|---|
| Lifeline | Doctor (Actor) และอีก 5 Object ภายในระบบ |
| Activation | แถบบนเส้น Lifeline ช่วงที่แต่ละ Object กำลังทำงาน |
| Call Message (เส้นทึบ หัวลูกศรทึบ) | ข้อความ 1, 2, 2.1, 3, 4, 4.1, 5, 6, 6.2, 6.4, 6.6 |
| Return Message (เส้นประ หัวลูกศรเปิด) | ข้อความ 2.2, 2.3, 2.4, 4.2, 6.3, 6.5, 6.7, 6.8, 6.9, 6.10, 6.11 |
| Self Message | 6.1 ตรวจสอบความครบถ้วนของข้อมูล (ExaminationController เรียกตัวเอง) |
| loop | การเลือกรหัสวินิจฉัย ICD-10 ที่ทำซ้ำได้หลายรายการ |
| alt | แยกกรณีข้อมูลครบถ้วน กับกรณีข้อมูลไม่ครบหรือเคสถูกปิดแล้ว |

# 2.1 Sequence Diagram (เลือก 1 Use Case จากแต่ละระบบย่อยที่รับผิดชอบ)

## Use Case ระบบย่อยที่ 2: สั่งยาให้ผู้ป่วย (Prescribe Medication)

### 1. การวิเคราะห์องค์ประกอบ (Participant Identification)

**Actor (External to the System):**

- **แพทย์ (Doctor)** — ผู้ออกคำสั่งใช้ยาให้ผู้ป่วย
- **เภสัชกร (Pharmacist)** — ผู้รับใบสั่งยาไปจ่ายยาต่อ (Secondary Actor ปลายทางของคำสั่ง)

**Object (Internal to the System):**

- **PrescriptionPage** — หน้าจอสั่งยา ใช้ค้นหายา ระบุขนาดและวิธีใช้ และยืนยันส่งใบสั่งยา
- **PrescriptionController** — ตัวควบคุม ตรวจสอบประวัติแพ้ยาและจำนวนคงเหลือ บันทึกใบสั่งยา และส่งต่อไปห้องยา
- **Medicine** — ข้อมูลคลังยา ใช้ค้นหายาและตรวจสอบจำนวนคงเหลือ
- **PatientHistory** — ประวัติแพ้ยาและยาที่ผู้ป่วยใช้อยู่ ใช้ตรวจสอบก่อนอนุญาตให้สั่งยา
- **Prescription** — ใบสั่งยาที่แพทย์ออก เก็บรายการยา ขนาด วิธีใช้ และจำนวน
- **PharmacyQueue** — คิวใบสั่งยาของห้องยา จุดส่งต่อระหว่างแพทย์กับเภสัชกร

### 2. การเขียน Scenario

**Main Scenario:**

1. แพทย์เปิดหน้าสั่งยาของเคสที่กำลังตรวจ
2. แพทย์ค้นหายาที่ต้องการสั่ง
3. PrescriptionController ค้นหายาในคลังจาก Medicine และส่งรายการยาพร้อมจำนวนคงเหลือกลับมาแสดง
4. แพทย์เลือกยา ระบุขนาด วิธีใช้ และจำนวน (ทำซ้ำได้จนครบทุกรายการที่ต้องการสั่ง)
5. PrescriptionController ตรวจสอบประวัติแพ้ยาของผู้ป่วยจาก PatientHistory และตรวจจำนวนคงเหลือของยา
6. เมื่อไม่พบประวัติแพ้ยาและจำนวนคงเหลือเพียงพอ ระบบเพิ่มรายการยานั้นลงใบสั่งยาและแสดงผลกลับ
7. แพทย์กดยืนยันส่งใบสั่งยา
8. PrescriptionController ตรวจสอบว่ามีรายการยาในใบสั่งอย่างน้อยหนึ่งรายการ
9. PrescriptionController บันทึกใบสั่งยาลง Prescription และจองจำนวนยาที่สั่งกับ Medicine
10. PrescriptionController ส่งใบสั่งยาเข้า PharmacyQueue และระบบแจ้งเตือนใบสั่งยาใหม่ไปยังเภสัชกร
11. ระบบแสดงสถานะ "รอเภสัชกรจ่ายยา" ให้แพทย์ทราบ

**Alternative Scenario:**

- **A1 ผู้ป่วยมีประวัติแพ้ยาที่แพทย์เลือก**
  ระบบไม่เพิ่มยานั้นลงใบสั่ง และแสดงคำเตือนพร้อมชื่อยาที่ผู้ป่วยแพ้ เพื่อให้แพทย์เลือกยาตัวอื่นแทน
- **A2 จำนวนยาคงเหลือในคลังไม่เพียงพอ**
  ระบบแจ้งจำนวนคงเหลือที่มีอยู่จริงและไม่เพิ่มรายการยานั้น เพื่อให้แพทย์ปรับจำนวนหรือเลือกยาทดแทน
- **A3 ยืนยันส่งใบสั่งยาโดยที่ยังไม่มีรายการยา**
  ระบบไม่บันทึกใบสั่งยาและแจ้งเตือนว่าใบสั่งยาว่าง
- **A4 ส่งใบสั่งยาเข้าคิวห้องยาไม่สำเร็จ**
  ระบบยกเลิกการบันทึกใบสั่งยาและคืนจำนวนยาที่จองไว้ (rollback)
  แล้วแจ้งเตือนให้แพทย์ส่งใบสั่งยาใหม่ เพื่อไม่ให้ยาถูกตัดสต็อกทั้งที่เภสัชกรไม่ได้รับใบสั่ง

| Activation | แถบบนเส้น Lifeline ช่วงที่แต่ละ Object กำลังทำงาน |
| Call Message (เส้นทึบ หัวลูกศรทึบ) | ข้อความ 1, 2, 2.1, 2.2, 3, 3.1, 3.2, 4, 4.1, 4.3, 4.5, 4.7, 4.8 |
| Return Message (เส้นประ หัวลูกศรเปิด) | ข้อความ 2.3, 2.4, 3.3, 3.5, 3.6, 3.7, 4.4, 4.6, 4.9, 4.10, 4.11, 4.12, 4.13 |

## วิธีเปิดไฟล์ไดอะแกรม

1. เข้า https://app.diagrams.net
2. File → Open From → Device แล้วเลือกไฟล์ `.xml` (หรือลากไฟล์ไปวางในหน้าเว็บได้เลย)
3. จัดตำแหน่งเพิ่มเติมได้ตามต้องการ
4. File → Export as → PNG (ติ๊ก Transparent Background ออก, Zoom 200% เพื่อให้ตัวหนังสือคมเวลาวางในเอกสาร)
